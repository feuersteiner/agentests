# INC-412: product images failing on storefronts

- Severity: SEV-2
- Lead: Priya Nair (platform on-call)
- Comms: Tom Becker (support)
- Current state: rollback in progress. Next public update due 11:00 UTC.

## Timeline, 23 November 2026 (UTC)

- 09:10 img-resizer v3.8.0 deployed (new WebP pipeline).
- 09:14 Alert: 5xx rate on /cdn/img/* above threshold.
- 09:25 Confirmed: product photos and collection thumbnails return 502 on storefronts whose
  theme asks for WebP. 2,310 of 12,840 active stores (18%), mostly Arbor and Dawnlight themes.
  Shoppers see grey boxes where the photos should be. Admin product editor shows broken
  thumbnails on the same stores; editing and saving products still works.
- 09:32 Status page component "Storefronts" set to degraded. No post yet.
- 09:40 Checkout funnel checked: checkout error rate flat, checkout pages don't use resized
  images. Order volume normal for a Monday.
- 09:48 Root cause: v3.8.0 rejects source images wider than 4,000 px and the fallback path
  returns 502 instead of the original.
- 09:50 Support emailed the affected merchants that we know about the image problem and will
  follow up.
- 09:55 Payments team: no anomalies in authorisations or payouts.
- 10:00 Storage team: original uploads untouched in the media bucket, only the resized copies
  fail to generate. Nothing lost, no re-uploads needed.
- 10:05 Decision: roll back img-resizer to v3.7.2.
- 10:20 Rollback started region by region. EU done, US in progress, expected complete about
  10:50.
