# Complex support 03: Broken approval history before the tender cutoff

This source-grounded fictional situation concerns data loss and recovery at
Flint Ledger for Meridian Works. Twenty ordered records separate metadata
availability, application consistency, accepted recent writes, incomplete backup
chains, customer-owned evidence and actual recovery permissions. A board briefing
and tender cutoff create real timing pressure while supplier reimbursement and
larger compensation claims have different approval scopes. The fictional decision
cutoff is **2025-05-14 12:00 UTC**.

Public inspiration comes from [GitLab's 2017 database incident](https://about.gitlab.com/blog/gitlab-dot-com-database-incident/),
[GitHub's October 2018 analysis](https://github.blog/news-insights/company-news/oct21-post-incident-analysis/)
and [Atlassian's April 2022 review](https://www.atlassian.com/blog/how-we-build/post-incident-review-april-2022-outage).
These are attributed company reports, not independent audits or fictional account
policy. Publication dates, redirect destinations, update uncertainty and actual
2026-11-23 retrieval dates appear in [sources.json](sources.json). Only short,
original factual paraphrases appear in E01. Their local hashes are not webpage
hashes. No open transcript license is asserted, and no raw source pages,
screenshots or real customer identifiers are included.

All business records, dialogue, contracts, staff, amounts and candidates are
synthetic. Five neutral candidate pairs address one business situation. They do
not constitute five independent cases. The six-dimensional ordinal rubric and
structured response schema support offline packet preparation; **graded model
evaluation is not implemented**. No model inference or measured performance claim
is part of this fixture.

[manifest.json](manifest.json) freezes ordered context, candidates, task, rubric,
response schema, provenance and reviewer bytes. [summary.json](summary.json) is a
navigation aid excluded from packets. Provisional cited
[reviewer expectations](reviewer/expectations.json) are also excluded. Those
expectations include distinct defensible resource allocations, a polished harmful
plan, an incomplete response and a contested expense interpretation. All expected
grades remain **synthetic, provisional and not human reviewed**. Agent content
review is separate from human label review and empirical evaluator validation.

Each packet contains the complete ordered context, normative task/rubric/schema
and exactly one completed reply/plan pair. Input-only preparation does not read
reviewer material; full validation checks its hash and cross-references separately.
UTF-8 byte and whitespace-word measurements come from actual finalized files.
Tokens remain null because no named tokenizer and encoding is configured. Full
serialized packet sizes include JSON overhead and are reported by offline
validation and the prepared inventory, separately from context measurements.

From the repository root, using installed dependencies:

```sh
bun --no-env-file --no-install benchmark/v2/workbench/dossier-cli.ts validate --case complex-support-03
bun --no-env-file --no-install benchmark/v2/workbench/dossier-cli.ts --help
```

Preparation writes only to a fresh ignored destination under
`benchmark/v2/results/prepared/`; see the suite CLI help for syntax. It does not
execute or grade models. No candidate expectations, other alternatives or source
selection judgments belong in an assessment packet.
